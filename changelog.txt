🔧 *BUG FIX*
━━━━━━━━━━━━━━━━━━━━━━
> NO.1 ⚡ *Koneksi Bot Utama & Userjadibot — Lambat karena File Session Menumpuk*
> Bug: folder session menyimpan banyak file yang terus bertambah → bot lambat konek & spam storage
> Fix: semua data session dipadatkan jadi 1 file per sesi (bot utama & setiap userjadibot)
> Hasil: koneksi jauh lebih cepat, tidak ada lagi spam file di folder session

> NO.2 🖼️ *Fitur .hd — Kini Berfungsi Normal*
> Bug: perintah .hd sebelumnya tidak bekerja / gagal memproses gambar
> Fix: fitur HD Upscaler (.hd / .remini / .hdr) kini berjalan normal
> Gambar berhasil diupscale dengan kualitas 4K / 6K / 8K via SparkPix AI

> NO.3 🛡️ *Eval — ReferenceError Tidak Lagi Bocor ke Log*
> Bug: perintah .eval / .> melempar ReferenceError ke console meski sudah ada try-catch
> Penyebab: error dari async eval tidak tertangkap dengan benar, bocor keluar handler
> Fix: async eval kini pakai Promise.resolve().catch() — semua error tertangkap bersih
> Tambahan: perintah .eval sekarang hanya bisa dipakai owner, non-owner diabaikan diam-diam

> NO.4 🔐 *Setting Jadibot — User Non-Owner Bisa Ubah Setting Sendiri*
> Bug: perintah .readsw / .antidel / .anticall / .anticallvid selalu return untuk non-owner
> Padahal outer guard sudah izinkan pemilik jadibot masuk ke handler
> Penyebab: inner guard `if (!m.isOwner) return` memblokir lagi di dalam handler
> Fix: inner guard kini cek isOwner ATAU pemilik sesi jadibot — keduanya diizinkan
> Berlaku untuk 4 perintah sekaligus: readsw, antidel, anticall, anticallvid

> NO.5 📛 *InformasiBotCommand — Nama Jadibot Tampil Salah*
> Bug: nama yang tampil di log .informasibot adalah nama pengirim (sender), bukan nama jadibot
> Fix: Nama kini diambil dari `hisoka.getName(jadibotJid)` — realtime dari kontak WA jadibot
> Nomor juga difix: tampil nomor jadibot itu sendiri, bukan nomor sender

> NO.6 🔍 *anticall / anticallvid — Deteksi isJadibot Tidak Konsisten*
> Bug: handler anticall & anticallvid pakai `jadibotMap.has(senderNum)` untuk deteksi jadibot
> Cara ini tidak akurat — bisa salah key / false positive / false negative
> Fix: disamakan dengan handler lain pakai `hisoka?.isMainBot === false` — konsisten & akurat

> NO.7 🌐 *Auto Online Bot Utama — Tidak Sengaja Kontrol Semua Jadibot*
> Bug: `startAutoOnline` bot utama pakai loop `jadibotMap.values()` → kirim presence ke SEMUA jadibot
> Akibatnya: setting online/offline bot utama mempengaruhi semua jadibot, tidak bisa independent
> Fix: loop jadibotMap dihapus dari startAutoOnline bot utama
> Kini setiap jadibot punya interval presence sendiri via `autoOnlineIntervalMap` yang isolated

🚀 *IMPROVEMENT*
━━━━━━━━━━━━━━━━━━━━━━
> NO.1 🗂️ *Folder src/scrape — Dirapikan Per Kategori*
> Sebelumnya file scraper campur jadi satu tanpa kategori
> Kini dipisah ke folder sesuai fungsinya:
> ai/ • download/ • anime/ • music/ • news/ • tools/ • system/
> Lebih mudah dikelola dan dikembangkan

> NO.2 🔔 *SwTrack — Notif Log Siapa yang Menghapus SW*
> Bot kini mencatat di log saat ada kontak yang menghapus SW (story/status)
> Berlaku di bot utama & tiap sesi userjadibot masing-masing
> Setiap userjadibot punya SwTrack sendiri, tidak campur satu sama lain

> NO.3 📟 *Log CMD Bot Utama & Userjadibot — Lebih Bersih & Ringkas*
> Sebelumnya log cmd penuh entri tidak perlu dari bot utama & jadibot
> Kini hanya cmd yang benar-benar dieksekusi yang tampil di log
> Log userjadibot tampil terpisah dari bot utama — mudah dibedakan

> NO.4 📦 *Hitungan Fitur Menu — Akurat Per-Fitur, Bukan Per-Alias*
> Sebelumnya: setiap alias dihitung sendiri → `.tt / .tiktok / .tik` = 3 fitur (inflate)
> Sesudahnya: satu case block = 1 fitur, alias tidak ikut dihitung
> Hasilnya: 242 alias → 123 fitur unik yang benar-benar akurat & realtime
> Berlaku di menu bot utama maupun menu jadibot

> NO.5 🤖 *Menu Jadibot — Tambah Kategori AUTO PRESENCE & Info Fitur Aktif*
> Menu jadibot kini tampilkan jumlah fitur yang tersedia untuk jadibot (realtime, per-block)
> Tambah kategori baru: ╭─「 💬 AUTO PRESENCE 」 berisi .online / .typing / .recording
> Header menu jadibot kini tampilkan: 📦 Fitur : X fitur aktif

> NO.6 📋 *.ceksetting — Tampilkan Status Auto Typing & Auto Recording*
> .ceksetting kini ikut tampilkan status ⌨️ Auto Typing dan 🎙️ Auto Recording
> Lengkap dengan detail: private/group on/off + delay aktif per fitur
> Footer hint diupdate: .typing • .recording masuk ke daftar perintah ubah setting

> NO.7 🔒 *Isolasi Data Per-Jadibot — Auto Online, Typing & Recording Tidak Bentrok*
> Setiap jadibot menyimpan setting Auto Online, Auto Typing, dan Auto Recording sendiri-sendiri
> Data tersimpan ke data_jadibot/settings.json dikelompokkan per nomor jadibot
> Jadibot A on typing tidak mempengaruhi jadibot B yang off typing — 100% isolated
> Auto Online punya interval timer sendiri (autoOnlineIntervalMap) per sesi jadibot
> Auto Typing & Recording hanya aktif saat ada pesan masuk ke sesi jadibot masing-masing
> Tidak ada shared state — restart bot utama / jadibot lain tidak reset setting jadibot ini

> NO.8 💾 *Auto-Init Emoji.json saat Jadibot Connect*
> Tidak perlu setup manual — emoji.json langsung terbuat saat jadibot pertama online
> Default 1900 emoji dari bot utama, mode default

> NO.9 🔄 *Mode Emoji Toggle Persistent — Tidak Hilang saat Restart*
> Mode emoji (default/custom) disimpan ke emoji.json per jadibot
> Saat bot restart atau jadibot reconnect, mode tetap seperti terakhir diset

> NO.10 🛡️ *Atomic Write untuk Semua Operasi Emoji*
> Semua tulis file emoji pakai pola .tmp → rename
> File tidak akan corrupt meskipun bot crash di tengah proses tulis

> NO.11 📁 *Pindah Lokasi Data Jadibot — data/jadibot → data_jadibot*
> Sebelumnya: semua data jadibot tersimpan di folder data/jadibot/{nomor}/
> Sesudahnya: dipindah ke data_jadibot/ di root project (sejajar index.js)
> Alasan: menghindari konflik dengan folder data/ bot utama & lebih mudah dikelola
> Mencakup: settings.json, realtime.json, session, dan file emoji per jadibot
> Semua referensi path di kode diupdate otomatis — tidak perlu migrasi manual
