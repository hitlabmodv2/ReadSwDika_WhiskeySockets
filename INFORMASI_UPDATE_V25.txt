*1. 🔗 AntiLink — Bulk Toggle "off all" / "on all"*
_Sekarang owner bisa atur AntiLink di semua grup sekaligus, tanpa satu-satu._
1. Tambah perintah `.antilink off all` — nonaktifkan AntiLink di *semua grup terdaftar*, khusus owner
2. Tambah perintah `.antilink on all` — aktifkan AntiLink di *semua grup terdaftar*, khusus owner
3. Status langsung tampil otomatis setelah toggle, digabung jadi *satu pesan* _(tidak dobel)_

*2. 🔗 AntiLink — "add all" / "del all" via Balas Status*
_Saat membalas pesan status AntiLink, cukup ketik satu kata untuk terapkan ke semua grup:_
• `add all` — tambahkan seluruh grup ke daftar aktif
• `del all` — hapus seluruh grup dari daftar aktif

*3. 👁️ .rvo2 — View Once Kirim ke DM Bot Sendiri*
_Varian baru dari `.rvo` — media view once dikirim langsung ke DM nomor bot, bukan ke chat asal:_
1. `.rvo` → media dikirim ke chat asal (GC tetap di GC, PM tetap di PM) — seperti sebelumnya
2. `.rvo2` → media dikirim ke *DM nomor bot itu sendiri* — aman & privat, tidak muncul di GC
3. Berlaku akurat untuk bot utama maupun jadibot — masing-masing kirim ke DM nomor bot-nya sendiri, tidak ada bentrok antar nomor
4. Konfirmasi ✅ + notif teks muncul di chat asal setelah media berhasil dikirim ke DM bot
> Berguna saat view once di GC tapi tidak mau media muncul ulang di GC — cukup ketik `.rvo2`, media langsung masuk DM bot

*4. 🖥️ .ramdisk / .diskram — Auto-Detect RAM & Disk Realtime, Simpan ke Config*
_Bot kini baca langsung RAM & disk dari server tempat bot jalan — bukan dari preset manual:_
1. Tambah fungsi `_getRealtimeStats()` — baca `os.totalmem()` / `os.freemem()` untuk RAM, dan `df -Pk` untuk disk
2. Disk dicari berurutan: `/home/container` _(Pterodactyl)_ → `process.cwd()` _(Replit/Railway/Fly)_ → `/` — otomatis cocok di semua hosting
3. Hasil tampil realtime di body pesan: bar visual `█░░░░░░░`, persentase, used/total/sisa, ikon 🟢🟡🔴 sesuai level
4. Saat `ramAutoDetect ON` — limit dihitung langsung `total RAM × persentase`, bukan angka tetap
5. Section baru *🤖 ᴀᴜᴛᴏ-ᴅᴇᴛᴇᴋꜱɪ & ꜱɪᴍᴘᴀɴ* ditambah di button single-select — posisi *paling atas* agar langsung terlihat:
   • _⚡ Save Semua Sekaligus_ — simpan RAM limit + disk limit + warn otomatis ke `config.json` dalam sekali klik
   • _🧠 Save RAM Limit_ — simpan `total RAM × persentase` ke config
   • _💾 Save Disk Limit_ — simpan total disk terdeteksi ke config
   • _⚠️ Save Warn Oto_ — set warn = usage disk sekarang + 10%, dibulatkan ke kelipatan 5 (max 95%)
6. Tombol Save Disk & Save Warn muncul dinamis — hanya tampil kalau disk berhasil terdeteksi
> Berlaku akurat di semua server: Pterodactyl, Replit, Railway, Fly.io — tanpa perlu config manual

*1. 🎭 EmojiMode Log SW — Selalu Tampil "Default 🔵" Padahal Sudah Custom*
~Bug: di log AutoReadStoryWhatsApp, baris EmojiMode selalu tampil "Default 🔵" meskipun user sudah set mode Custom~
1. _Penyebab:_ `event.js` pakai `getJadibotEmojiMode()` yang baca dari `data_jadibot/<nomor>/emoji.json` — padahal bot utama simpan mode di `src/helper/emoji.json`
2. _Fix:_ diganti ke `getMode()` dari `emoji.js` yang baca file yang benar untuk bot utama
3. _Catatan:_ jadibot tidak terpengaruh — sudah benar sejak awal _(baca dari `data_jadibot/<nomor>/emoji.json`)_
> EmojiMode kini tampil akurat realtime sesuai mode aktif, tanpa restart bot

*2. 🔗 AntiLink "off all" Tidak Sinkron dengan config.json*
~Bug: setelah `.antilink off all`, `config.json` masih tampil `antiLink.enabled: true` walau tidak ada grup aktif tersisa~
1. _Fix:_ `off all` langsung set `antiLink.enabled: false` di `config.json` karena sudah pasti nol grup aktif
2. _Fix:_ `off` (single grup) ikut set `enabled: false` kalau ternyata itu grup aktif terakhir
3. _Fix:_ `del` / `del all` via balas status juga ikut set `enabled: false` saat hasilnya nol grup aktif
4. _Tetap seperti semula:_ `on all`, `on`, `add`, `add all` otomatis set `enabled: true`
> Status global AntiLink kini akurat realtime, selalu mencerminkan kondisi grup yang sebenarnya

*3. ❌ AntiTagSW Error "isAntiTagSWEnabled is not a function"*
~Bug: perintah `.antitagsw` selalu gagal dengan error tersebut~
1. _Penyebab:_ `message.js` tidak meneruskan beberapa dependency ke handler `.antitagsw`, di antaranya:
   • `isAntiTagSWEnabled`
   • `saveCekautoTimestamp`
   • `getAllAntiTagSWGroups`, `getWarnings`, `resetWarnings`, `kvGet`, dll
2. _Fix:_ semua parameter yang dibutuhkan sudah dilengkapi di pemanggilan handler
> `.antitagsw` kini berjalan normal tanpa error

*4. 📋 InformasiBotCommand Duplikat di Semua Perintah*
~Bug: setiap perintah (`.ram`, `.ping`, dll) selalu muncul dua kotak InformasiBotCommand di log konsol~
1. _Penyebab:_ `message.js` punya pemanggilan `_logCmdBox` global tepat setelah guard lolos (log pertama), lalu setiap handler juga memanggil `logCommand` di dalamnya (log kedua)
2. _Fix:_ hapus blok `_logCmdBox` global dari `message.js` — cukup log dari dalam handler masing-masing
> InformasiBotCommand kini tampil tepat satu kali per perintah

*5. 🤖 .listbot — Reply `1,p` Hapus Data Bot (Permanent)*
~Bug: reply `1,p` dari `.listbot` memanggil `removeJadibotExpiry` yang menghapus seluruh entri data bot~
1. _Penyebab:_ handler salah panggil `removeJadibotExpiry` alih-alih `setPermanentJadibot`
2. _Fix:_ diganti ke `setPermanentJadibot(targetNum, 'active')` — data bot tersimpan benar, `Sisa: Permanent` tampil akurat
> Bot permanent kini aman saat diubah via reply `.listbot`

*6. 🤖 .listbot — Bot Permanent Tetap Tampil "Permanent" Setelah Diubah ke Durasi Terbatas*
~Bug: reply `1,1h` pada bot Permanent tidak mengubah tampilan `Sisa` & `Expire` — tetap "Permanent"~
1. _Penyebab:_ `extendJadibotExpiry` menyebarkan `permanent: true` dari data lama via spread `...existing` tanpa menimpanya
2. _Fix:_ tambah `permanent: false` eksplisit di objek hasil — flag dibersihkan, `Sisa` & `Expire` berubah realtime sesuai durasi baru
> Perubahan durasi dari/ke Permanent kini akurat dan langsung tercermin di `.listbot`

*7. 📡 Log "[SwTrack] SW dihapus" Kadang Tercatat Dobel/Lebih*
~Bug: saat sebuah status WhatsApp dihapus pengirimnya, log "SW dihapus" untuk ID story yang sama kadang muncul 2x bahkan lebih~
1. _Penyebab:_ event revoke status bisa terkirim lebih dari sekali (tipe `notify` & `append`, atau terkirim ulang saat bot reconnect/restart), dan kode lama tidak punya penanda permanen kalau ID itu sudah pernah dicatat
2. _Fix:_ penanda "sudah dicatat" sekarang diambil dari flag `deleted` yang tersimpan di file (persisted), bukan cuma di memori — jadi tetap akurat walau bot restart/reconnect berkali-kali
3. _Tambahan:_ penjagaan cepat di memori untuk hindari scan file berulang saat event sama datang beruntun dalam hitungan milidetik, dengan pembersihan otomatis tiap 5 menit
4. _Catatan:_ log dengan tag `[JB:<nomor>]` bukan duplikat — itu memang sesi jadibot terpisah yang independen mendeteksi story yang sama
> Log "SW dihapus" kini 100% akurat, satu ID story hanya tercatat tepat satu kali

*8. 🗑️ .d / .del — Reply Hapus Pesan Gagal Padahal Bot Sudah Admin Grup*
~Bug: reply pesan (lama maupun baru) dengan `.d` sering ditolak "Bot bukan admin di grup ini" walau bot sebenarnya sudah admin~
1. _Penyebab:_ pengecekan admin cuma baca dari cache `botadmin/botadmin` — kalau cache basi/telat sync (event promote kelewat, dll), status yang kebaca tetap "bukan admin"
2. _Fix:_ kalau cache bilang bukan admin/belum ada data, sekarang dicek ulang langsung (live) ke `groupMetadata` sebelum ditolak, lalu cache-nya otomatis diperbarui
3. _Catatan:_ hapus pesan milik bot sendiri (`fromMe`) tidak terpengaruh — jalur itu sudah akurat sejak awal untuk pesan lama maupun baru
> `.d` / `.del` kini akurat realtime, tidak lagi salah tolak gara-gara cache admin basi

*9. 📊 MemoryMonitor Log — Nomor "cek ke-N" Meloncat, Tidak Urut*
~Bug: log konsol tampil "cek ke-1" lalu langsung "cek ke-10", meloncat karena pakai nomor cek internal bukan nomor tampil~
1. _Penyebab:_ counter yang ditampilkan (`_checkCount`) dihitung dari setiap siklus cek memori, padahal log cuma diprint 1 dari tiap 10 siklus
2. _Fix:_ tambah counter terpisah (`_logCount`) yang hanya bertambah saat log benar-benar tampil di konsol
> "cek ke-N" kini urut 1, 2, 3, dst sesuai realtime, tidak ada lagi lompatan angka

*10. 🔌 Auto-Jadibot Setelah Downtime Lama — Sebagian Konek, Sebagian Tidak Merespon*
~Bug: setelah bot mati 1+ jam lalu hidup lagi, dari 8+ jadibot tersimpan hanya sebagian yang konek & merespon, sisanya diam~
1. _Penyebab:_ saat startup, semua sesi jadibot di-start *bersamaan dalam sekejap* (paralel tanpa jeda) — WhatsApp mendeteksi banyak koneksi baru dari 1 IP secara serentak dan sebagian di-reset/rate-limit, ditambah spike CPU/RAM saat baca banyak file sesi besar bersamaan
2. _Fix:_ startup jadibot sekarang berjalan *berurutan dengan jeda 3.5 detik* antar nomor — tiap koneksi jadibot "napas" sendiri, tidak bentrok dengan bot utama maupun jadibot lain
3. _Catatan:_ reconnect otomatis per-jadibot saat disconnect satuan (bukan saat startup massal) sudah aman sejak awal — sudah ada guard anti-duplikat dan delay 3 detik
> Semua jadibot kini konek bergiliran & stabil setelah downtime, tidak ada lagi yang "diam" karena rebutan resource/koneksi

*11. 👁️ .rvo — Jadibot Kirim ke Owner, Bukan ke Chat Asal*
~Bug: saat user jadibot pakai `.rvo` di GC atau PM, media view once malah dikirim ke semua nomor owner, bukan ke chat tempat perintah dikirim~
1. _Penyebab:_ handler punya cabang `if (hisoka.isMainBot === false)` yang loop ke semua owner JID alih-alih kirim ke `m.from`
2. _Fix:_ cabang jadibot dihapus — handler kini selalu `sendMessage(m.from, ...)` tanpa pengecualian
3. _Catatan:_ bot utama tidak terpengaruh — jalurnya sudah benar sejak awal
> `.rvo` kini akurat di semua kondisi: GC → reply di GC, PM → reply di PM, jadibot → reply di chat jadibot masing-masing tanpa bentrok

2. Judul section di button pakai *small-caps Unicode* — contoh: `ꜱᴛᴀᴛᴜꜱ ᴍᴏɴɪᴛᴏʀ`, `ᴀᴜᴛᴏ-ᴅᴇᴛᴇᴋꜱɪ & ꜱɪᴍᴘᴀɴ`
3. Body pesan sekarang tampilkan *Realtime RAM* dan *Realtime Disk* langsung dari server — bar visual `█░`, persentase, used/total/sisa, ikon 🟢🟡🔴
4. Urutan section button diubah — *🤖 Auto-Deteksi & Simpan* dipindah ke *posisi paling atas* agar langsung terlihat saat button dibuka
5. Save Disk & Save Warn juga muncul terintegrasi di dalam section Disk Limit & Warn — pilihan auto dan manual berdampingan
> Tampilan lebih konsisten dengan gaya button fitur lain (`.online`, `.typing`, dll) dan langsung terbaca tanpa scroll

*15. 🤖 .wilyai — Tombol Single-Select Realtime + Notif Fitur Belum Aktif*
_Perintah `.wilyai` kini tampil dengan button interaktif single-select, realtime status per fitur, persis pola `.online` & `.readsw`:_
1. Ketik `.wilyai` tanpa argumen → langsung muncul button pilihan, tidak lagi teks statis
2. Button punya *5 section* yang merangkum semua pengaturan AI:
   • *🤖 Status .wily / .ai / .tanya* — pilih Aktifkan atau Matikan perintah AI
   • *💬 Auto Reply AI* — pilih ON atau OFF untuk auto balas
   • *🤖 Auto Simi (AI Mention / Reply)* — pilih ON atau OFF untuk auto balas saat di-mention/reply
   • *🎯 Scope Auto Reply* — pilih 🌐 Semua, 📩 Private Only, atau 👥 Grup Only
   • *🗑️ History & Memori* — Reset semua sesi + memori user sekaligus
3. *Notif realtime fitur belum aktif* — jika ada fitur yang OFF, body button langsung tampil:
   _⚠️ X fitur belum aktif: ❌ Fitur .wily / ❌ Auto Reply AI / ❌ Auto Simi_
4. Baris pilihan yang fiturnya *OFF* langsung berubah label → `🔴 Aktifkan Sekarang` dengan deskripsi `⬆️ Belum aktif — Tap untuk aktifkan!` — tidak perlu tebak-tebak mana yang perlu dinyalakan
5. Pilihan yang *sedang aktif* diberi tanda `✓` di depannya dan deskripsi `⚡ Sedang Aktif — ...`
6. Setiap aksi (on/off, replay, scope, autosimi, reset) → button *terupdate otomatis* setelah berhasil, baca config fresh — status selalu akurat
7. Auto-delete pesan button sebelumnya sebelum kirim yang baru — tidak tumpuk-tumpuk di chat
8. Fallback ke teks biasa otomatis jika device tidak support button
> Semua pengaturan WilyAI kini bisa diakses dari satu button; fitur yang mati langsung kelihatan dan bisa dinyalakan dari sana
