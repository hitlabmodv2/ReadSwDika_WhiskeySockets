*3. 🔧 `hotReload.js` — Auto-Discovery + Deteksi File Baru/Hapus Real-Time*
- Sebelumnya file baru harus didaftarkan manual satu-satu supaya bisa hot-reload
- Sekarang bot otomatis scan & watch seluruh folder `SEMUA_FITUR`, `src/helper`, `src/db`, `src/config` secara rekursif — file apapun di dalam folder tersebut langsung ter-cover
- *File baru terdeteksi otomatis*: saat file `.js`/`.cjs` ditambahkan ke folder yang diawasi, langsung di-detect & di-watch — log tampil `[HotReload] File baru terdeteksi (CJS/ESM, auto-watched)`
- *File dihapus terdeteksi otomatis*: saat file dihapus/di-rename, langsung dilepas dari daftar watch — log tampil `[HotReload] File dihapus, dilepas dari watch` — tidak ada nyangkut/error
- *ESM* (`.js`): di-reload ulang via dynamic import dengan cache-busting URL (`?t=timestamp`) — modul langsung aktif versi terbaru
- *CJS* (`.cjs`): lazy — `require.cache` dibersihkan saat file berubah, sehingga efektif di pemanggilan berikutnya tanpa restart
- Debounce *600ms* — cegah trigger ganda saat file ditulis berulang cepat (misal auto-save editor)
- `message.js` diwatch tersendiri (bukan lewat recursive folder) via `EXTRA_ESM_FILES`
- `KEY_OVERRIDES` — key konsisten untuk file tertentu (antitagsw, event, emoji, menu, dll) walau path-nya berubah
- `EXCLUDED_FILES` — file yang sengaja di-skip dari hot-reload: `crashGuard`, `memoryMonitor`, `jadibot`, `authState`, `browserSwitch`, `aiHistory`, dan CJS startup (wm, cekauto, musikai, dll) — kalau direload bisa bikin state ganda/crash
- Export tambahan: `getReloadStats()` (total/ESM/CJS/folder aktif/excluded), `getWatchedFiles()` (semua file terlacak), `onReload(key, cb)` (callback pasca-reload), `stopHotReload()` (matikan semua watcher)
> File baru/dihapus langsung terdeteksi real-time — tidak perlu edit `hotReload.js` manual sama sekali

*1. 🎭 EmojiMode Log SW — Selalu Tampil "Default 🔵" Padahal Sudah Custom*
- ~Bug: di log AutoReadStoryWhatsApp, baris EmojiMode selalu tampil "Default 🔵" meskipun user sudah set mode Custom~
- Penyebab: `event.js` pakai `getJadibotEmojiMode()` yang baca dari `data_jadibot/<nomor>/emoji.json` — padahal bot utama simpan mode di `src/helper/emoji.json`

- Jadibot tidak terpengaruh — sudah benar sejak awal (baca dari `data_jadibot/<nomor>/emoji.json`)
> EmojiMode kini tampil akurat realtime sesuai mode aktif, tanpa restart bot

*2. 💾 Command `.ram` — Error "formatUptime is not a function"*
- ~Bug: saat ketik `.ram`, muncul error `[CekRAM] Error: formatUptime is not a function`~
- Penyebab: bot yang sedang berjalan masih memakai versi lama `memoryMonitor.js` di memori (ESM cache), belum ke-reload setelah fungsi `formatUptime` ditambahkan
- Fix: restart proses bot supaya modul ter-load ulang; `.ram` sekarang juga ditampilkan lebih lengkap (Heap, External memory, RAM free, CPU Load, PID, versi Node, Uptime)
> `.ram` sudah normal, data akurat, sudah diuji langsung tanpa error

*3. 🔁 Command Ke-Eksekusi 2x — Log `InformasiBotCommand` Muncul Duplikat (dedup guard)*
- ~Bug: kirim command sekali (misal `.readsw`), tapi log `InformasiBotCommand` muncul 2x dengan waktu identik — command ikut ke-eksekusi dobel~
- Penyebab: event `messages.upsert` dari WhatsApp kadang re-deliver pesan yang sama (msg ID sama) tanpa ada dedup guard, jadi handler pesan jalan 2x untuk 1 pesan
- Fix: tambah dedup guard di `index.js` — tiap `message.key.id` yang sudah diproses langsung di-skip kalau muncul lagi dalam 60 detik
> Semua command sekarang cuma jalan sekali per pesan, tidak ada lagi eksekusi/log dobel

*4. 📋 `InformasiBotCommand` Muncul Duplikat — Double Logging di `message.js`*
- ~Bug: kirim command sekali tapi log `InformasiBotCommand` muncul 2 kali dengan waktu identik~
- Penyebab: ada 2 tempat logging — satu di `message.js` (terpusat, sebelum switch, hanya untuk command di `_commandSet`) dan satu lagi di dalam tiap handler — kalau command ada di `_commandSet`, ikut ter-log 2x
- Fix: hapus blok `_logCmdBox` terpusat di `message.js` — logging diserahkan sepenuhnya ke tiap handler masing-masing yang sudah konsisten memanggil `logCommand`
- Perubahan di `message.js`
> `InformasiBotCommand` kini selalu muncul tepat 1x per command, tidak pernah dobel lagi

*5. 🔤 Prefix Hardcoded `.` di Respons `.emojilist`*
- ~Bug: di body text command `.emojilist`, semua contoh command pakai prefix hardcoded `.` (misal `.emojiadd`) — tidak ikut prefix yang diset pengguna~
- Penyebab: string command di bodyText menggunakan literal `.` bukan variabel `${pref}`
- Fix: semua contoh command di respons `.emojilist` diganti ke `${pref}emojiadd`, `${pref}emojidel`, dst.
- Perubahan di `SEMUA_FITUR/info/info.cjs` (handleEmojilist)
> Prefix command di respons sekarang selalu akurat sesuai prefix yang dipakai pengguna

*6. 🦖 `start-ptero.sh` — Bot Berhenti Diam Tanpa Restart di Panel Pterodactyl*
- ~Bug: bot yang jalan di panel Pterodactyl bisa crash/berhenti diam-diam tanpa restart otomatis — panel menampilkan "Online" tapi bot tidak merespons~
- Fix: script `start-ptero.sh` khusus untuk Pterodactyl — set *Startup Command* di panel ke `bash start-ptero.sh`, bot langsung terlindungi
- Auto-restart loop: bot di-restart otomatis setiap kali crash/exit (maks 10x), dengan jeda 5 detik antar restart
- Auto-install: jika `node_modules` belum ada saat panel pertama jalan, langsung `npm install` otomatis
- Notifikasi Telegram: kirim pesan saat bot start, crash+restart, dan laporan harian (uptime, total restart, memori server) — aktif jika `telegram.enabled: true` di `config.json`
- Bisa diterapkan di masing-masing panel secara independen
> Bot tidak akan pernah diam diam-diam lagi — selalu restart sendiri dan lapor via Telegram
