*1. 🎭 EmojiMode Log SW — Selalu Tampil "Default 🔵" Padahal Sudah Custom*
- ~Bug: di log AutoReadStoryWhatsApp, baris EmojiMode selalu tampil "Default 🔵" meskipun user sudah set mode Custom~
- Penyebab: `event.js` pakai `getJadibotEmojiMode()` yang baca dari `data_jadibot/<nomor>/emoji.json` — padahal bot utama simpan mode di `src/helper/emoji.json`
- Fix: diganti ke `getMode()` dari `emoji.js` yang baca file yang benar untuk bot utama
> EmojiMode kini tampil akurat realtime sesuai mode aktif, tanpa restart bot

*2. 💾 Command `.ram` — Error "formatUptime is not a function"*
- ~Bug: saat ketik `.ram`, muncul error `[CekRAM] Error: formatUptime is not a function`~
- Penyebab: bot yang sedang berjalan masih memakai versi lama `memoryMonitor.js` di memori (ESM cache)
- Fix: restart proses bot supaya modul ter-load ulang; `.ram` sekarang juga ditampilkan lebih lengkap
> `.ram` sudah normal, data akurat, sudah diuji langsung tanpa error

*3. 🔁 Command Ke-Eksekusi 2x — Log `InformasiBotCommand` Muncul Duplikat (dedup guard)*
- ~Bug: kirim command sekali, tapi log `InformasiBotCommand` muncul 2x dengan waktu identik~
- Penyebab: event `messages.upsert` dari WhatsApp kadang re-deliver pesan yang sama tanpa dedup guard
- Fix: tambah dedup guard di `index.js` — tiap `message.key.id` yang sudah diproses langsung di-skip dalam 60 detik
> Semua command sekarang cuma jalan sekali per pesan, tidak ada lagi eksekusi/log dobel

*4. 📋 `InformasiBotCommand` Muncul Duplikat — Double Logging di `message.js`*
- ~Bug: kirim command sekali tapi log `InformasiBotCommand` muncul 2 kali~
- Penyebab: ada 2 tempat logging — satu terpusat di `message.js` dan satu di dalam tiap handler
- Fix: hapus blok `_logCmdBox` terpusat di `message.js` — logging diserahkan ke tiap handler
> `InformasiBotCommand` kini selalu muncul tepat 1x per command

*5. 🔤 Prefix Hardcoded `.` di Respons `.emojilist`*
- ~Bug: semua contoh command di respons `.emojilist` pakai prefix hardcoded `.` — tidak ikut prefix user~
- Fix: semua contoh command diganti ke `${pref}emojiadd`, `${pref}emojidel`, dst.
- Perubahan di `SEMUA_FITUR/info/info.cjs` (handleEmojilist)
> Prefix command di respons sekarang selalu akurat sesuai prefix yang dipakai pengguna

*6. 🦖 `start-ptero.sh` — Bot Berhenti Diam Tanpa Restart di Panel Pterodactyl*
- ~Bug: bot di panel Pterodactyl bisa crash/berhenti diam-diam tanpa restart otomatis~
- Fix: `start-ptero.sh` dengan auto-restart loop (maks 10x), auto-install, notifikasi Telegram
> Bot tidak akan pernah diam-diam lagi — selalu restart sendiri dan lapor via Telegram

*7. 🖼️ Fitur Waifu — Error HTTP 403/401 di Panel Pterodactyl*
- ~Bug: pilih kategori Safe maupun NSFW di `.waifu`, semua gagal dengan error HTTP 403 atau 401~
- Penyebab: tbib.org memblokir IP range VPS/Pterodactyl (OVH, Hetzner, dll) — IP Replit (Google Cloud) tidak diblok; gelbooru.com dan rule34.xxx juga terbukti minta auth (401)
- Fix: sistem fallback bertingkat — tbib.org → safebooru.org (mode Safe) / xbooru.com (mode NSFW)
  Kedua fallback terbukti HTTP 200 dari IP datacenter manapun, tidak perlu auth/API key
  Fallback aktif otomatis jika tbib.org return 403, 401, 429, 503, timeout, atau ECONNREFUSED
- Perubahan di `SEMUA_FITUR/anime/waifu.cjs` (`_fetchWaifu`, `_fetchSafebooru`, `_fetchXbooru`)
> Fitur waifu kini work di Replit maupun panel Pterodactyl tanpa perlu konfigurasi tambahan

*8. 🖼️ Fitur Waifu — Error "Protocol http: not supported. Expected https:"*
- ~Bug: setelah fallback ke xbooru.com, gambar gagal diunduh dengan error protocol http~
- Penyebab: xbooru.com kadang mengembalikan `file_url` dengan protokol `http://`, sedangkan `_downloadBuffer` menggunakan modul `https` Node.js yang hanya mendukung HTTPS
- Fix: `_downloadBuffer` diubah untuk mendeteksi protokol URL secara otomatis — jika `http://` pakai modul `http`, jika `https://` pakai modul `https`
- Perubahan di `SEMUA_FITUR/anime/waifu.cjs` (`_downloadBuffer`)
> Download gambar dari sumber manapun (http maupun https) tidak akan error lagi
