1. *HENTAIDAD — Pencarian Galeri*
   ~Sebelumnya, hasil pencarian tidak muncul di WhatsApp.~
   • Memperbarui selector DOM agar cocok dengan struktur situs saat ini.
   • Selector yang digunakan: `article.post-card`, `a.archive-card-link`, dan `h2.archive-card-title`.
> _Hasil: kartu galeri dapat dibaca dari halaman pencarian._

2. *HENTAIDAD — Jumlah Gambar Tidak Akurat*
   ~Sebelumnya, thumbnail dapat ikut terhitung sebagai foto galeri.~
   • `scrapeGallery` mengecualikan thumbnail `-thumb.webp` dan `/thumbnails/`.
   • Metadata diambil dari `.post-meta`: tanggal, views, jumlah gambar, dan rating.
> _Hasil: jumlah foto galeri dan metadata tampil lebih akurat._

3. *WAIFU — Parameter API NSFW/Safe*
   ~Sebelumnya, parameter `is_nsfw` tidak bekerja sehingga mode NSFW tetap muncul gambar Safe.~
   • Ganti parameter dari `is_nsfw` ke `isNsfw` (camelCase).
   • Random Safe & NSFW sesuai web `https://www.waifu.im/gallery`.
   • Footer & source diganti dari `tbib.org` ke `waifu.im`.
> _Hasil: mode NSFW mengirim gambar Explicit (NSFW), mode Safe mengirim gambar aman._

4. *PIXIV — Album Multi-Gambar*
   ~Sebelumnya, gambar terkirim terpisah satu per satu, bukan dalam 1 album.~
   • Ganti struktur album dari `albumMessage` ke format Baileys terbaru: `{ album: { expectedImageCount } }` + `albumParentKey`.
   • Pola sama dengan `hentaidad.cjs` — kirim pesan parent dulu, baru kirim gambar dengan `albumParentKey`.
   • Fallback ke pengiriman terpisah jika album gagal.
> _Hasil: `.pixiv megumin,5` kirim 5 gambar dalam 1 album WhatsApp._

5. *PIXIVR18 — Backend & Album Multi-Gambar*
   ~Sebelumnya, Pixiv API R18 tanpa login mengirim gambar SFW (`xRestrict:0`), dan gambar terkirim terpisah.~
   • Backend diganti dari Pixiv ke nHentai (`nhentai.to`) untuk menjamin 100% konten NSFW real-time.
   • Struktur album sama dengan `pixiv.cjs` — kirim parent + `albumParentKey`.
   • Fetch galeri paralel, ambil random page dari tiap galeri, lalu download concurrent.
> _Hasil: `.pixivr18 yuri,5` kirim 5 gambar NSFW dalam 1 album, dijamin R18._

6. *READSW — Retry Mengikuti Mode Tiap Story*
   ~Sebelumnya, story Read Only yang sudah dibaca dapat dianggap belum bereaksi setelah mode diubah, lalu mendapat reaksi dari startup atau live retry.~
   • Simpan `reactionExpected` pada tiap entri agar Read Only dapat dibedakan dari reaksi yang memang tertunda.
   • Startup dan live retry hanya mengirim reaksi jika entri mencatat `reactionExpected:true` dan konfigurasi terbaru masih mengizinkan reaksi.
   • Entri lama tanpa penanda tidak dianggap sebagai reaksi gagal; story yang belum terbaca tetap dapat diproses ulang.
   • Log mode menampilkan `Read Only 👁️` atau `Read+Reaction ✓` sesuai mode proses.
> _Hasil: perubahan mode tidak memicu reaksi balik pada story lama Read Only; retry tetap memproses story belum terbaca dan reaksi yang memang diharapkan._

7. *MUSIKAI & MUSIKAI2 — Dihentikan (Backend API Tidak Gratis)*
   ~Fitur `.musikai` dan `.musikai2` telah dihentikan karena backend API (`api.chatmusicpro.com`) tidak lagi menyediakan layanan gratis.~
   • Error: `Generate gagal: Insufficient balance, please recharge` — backend memerlukan pembayaran.
   • Login via `device_login` gagal di semua `source_site` dan `app-market`.
   • Fitur sudah dihapus dari router, menu, dan helper.
   • User akan menerima pesan penolakan jika mencoba `.musikai` atau `.musikai2`.
> _Hasil: Fitur tidak akan error, user mendapat notifikasi jelas bahwa fitur dihentikan._
